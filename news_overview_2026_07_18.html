What is “loop engineering?”
14.07.2026
Loop engineering ersetzt das manuelle Prompten durch automatisierte Schleifen, die AI-Agenten kontinuierlich Aufgaben abarbeiten, bis definierte Ziele erreicht sind. Die Methode begann mit dem „Ralph Wiggum“ Loop, einem Bash-Skript, das mittels wiederholter Agentenaufrufe eine dynamische Aktualisierung eines Masterplans ermöglicht und damit Kontextfenster-Limitationen (ca. 200.000 Token) umgeht. Der /goal-Befehl – erstmals in Codex (CLI 0.128.0) und kurz darauf auch in Hermes und Claude Code implementiert – kapselt diesen Ansatz, indem er eine persistente Zielvorgabe an den Agenten übergibt, der dann eigenständig weitere Schritte generiert, bis das Endkriterium erfüllt ist. Praktische Anwendungsfälle umfassen Trigger-basierte Automatisierungen, Cron-Job-ähnliche Abläufe für PR-Erstellungen, Teststabilisierung und migrationsbezogene Aufgaben, wobei auch Herausforderungen wie Agenten-Drift und steigende Token-Kosten thematisiert werden. Entwickler nutzen Loop engineering somit, um regelmäßig wiederkehrende Prozesse effizient in bestehende Workflows zu integrieren und strategische Abläufe fast autonom zu steuern.

How to build a cloud software factory - self-improving code review
15.07.2026
Der Beitrag demonstriert, wie sich in einer Cloud Software Factory ein Code-Review-Agent entwickeln lässt, der sich mit einem Outer-Loop-Mechanismus automatisch verbessert. Der Code-Review-Skill, basierend auf einem Template, das auch im populären OSS-Repository von Warp verwendet wird, nimmt als Eingaben den PR-Beschreibungstext, den Code-Diff und gegebenenfalls Spezifikationen eines Spec-Agents entgegen und liefert ein strukturiertes JSON (review.json) als Ergebnis. Durch die Integration von GitHub Actions und Cloud Agents wie Claude Code, Codex und Warp Agent wird der Skill bei PR-Änderungen ausgelöst, wobei der Agent mit Lesezugriff agiert, um Sicherheitsrisiken wie Prompt Injection zu vermeiden. Ein separater Outer-Loop-Agent wertet täglich das menschliche Feedback zu den Reviews aus und erstellt automatisiert Pull Requests, um den Code-Review-Skill an team- und repositoryspezifische Konventionen anzupassen.
